# 管理后台使用指南

本文档介绍从零开始通过管理后台发布一张专辑的完整流程，包含文件上传、数据录入、前端发布与常见问题。

## 1. 管理后台是什么

管理后台位于 `http://localhost:8000/admin`，基于 SQLAdmin 构建，用于在浏览器中维护四类数据：

- 专辑（albums）
- 曲目（tracks）
- 制作人/音乐人（artists）
- 署名（credits：专辑或曲目与制作人的关联）

音频和封面文件不直接通过后台页面上传，而是通过上传接口保存到服务器磁盘，再把返回的路径填入对应字段。

## 2. 启动与登录

### 2.1 启动后端

```bash
cd backend
source .venv/bin/activate
cp .env.example .env   # 首次使用；修改其中的 DATABASE_URL
python scripts/init_db.py
uvicorn app.main:app --reload --port 8000
```

`init_db.py` 只需在数据库首次使用或重建后执行；之后正常启动后端即可。

### 2.2 登录

浏览器打开 `http://localhost:8000/admin`，使用默认账号：

```text
用户名：admin
密码：admin
```

生产环境部署前必须修改账号密码，见本文档第 7 节。

## 3. 界面结构

登录后左侧有四个菜单：

| 菜单 | 管理内容 |
| --- | --- |
| 专辑 | 专辑标题、URL 标识、封面、发行日期、简介、发布状态 |
| 曲目 | 曲名、所属专辑、曲号、时长、音频路径、歌词 |
| 制作人 | 姓名 |
| 署名 | 专辑/曲目与制作人的关联 |

点击行可进入编辑页，列表右上角有新建按钮。

## 4. 从头添加一张专辑的完整流程

建议按以下顺序操作，避免出现“曲目找不到专辑”之类的问题。

### 步骤 1：添加制作人

1. 进入“制作人”菜单，点击新建
2. 填写姓名，例如“Soul Searching”
3. 保存

后续在署名里可以通过下拉框搜索选择，不需要手工记 ID。

### 步骤 2：上传封面

在终端执行（`admin:admin` 换成实际账号）：

```bash
curl -u admin:admin -F "file=@/path/to/cover.jpg" \
  http://localhost:8000/api/v1/uploads/cover
```

成功返回：

```json
{
  "path": "covers/xxxxxxxx.jpg",
  "url": "/media/covers/xxxxxxxx.jpg"
}
```

复制 `path` 的值（即 `covers/xxxxxxxx.jpg`），下一步填入专辑。

### 步骤 3：上传音频

每首曲目上传一次：

```bash
curl -u admin:admin -F "file=@/path/to/01.mp3" \
  http://localhost:8000/api/v1/uploads/audio
```

返回：

```json
{
  "path": "audio/xxxxxxxx.mp3",
  "url": "/media/audio/xxxxxxxx.mp3"
}
```

分别记录每首曲目对应的 `path`。

### 步骤 4：创建专辑

1. 进入“专辑”菜单，点击新建
2. 填写字段：
   - URL 标识（slug）：唯一，用于网址，建议用英文/拼音，如 `first-light`
   - 标题：专辑名
   - 封面路径：粘贴步骤 2 的 `covers/xxx.jpg`
   - 发行日期：可选
   - 简介：可选
   - 已发布：勾选后才会出现在前端
3. 保存

### 步骤 5：创建曲目

1. 进入“曲目”菜单，点击新建
2. 填写字段：
   - 所属专辑：下拉框搜索专辑标题后选择
   - 标题：曲名
   - 曲号：从 1 开始，决定曲目顺序
   - 时长（秒）：可选，填了播放器会显示时长
   - 音频路径：粘贴步骤 3 对应曲目的 `audio/xxx.mp3`
   - 歌词：可选，纯文本，按换行显示
     - 需要滚动高亮时，在每行开头添加 `[mm:ss.xx]` 时间戳，例如：
       `[00:12.50]第一句歌词`
     - 没有歌词的曲目，播放器页会显示所属专辑的“简介”
3. 保存
4. 每首曲目重复一次

### 步骤 6：创建署名

署名有两种：

- 专辑级署名：整张专辑的制作人
- 曲目级署名：某首曲目的作曲/编曲等

1. 进入“署名”菜单，点击新建
2. 填写字段：
   - 专辑：专辑级署名时选择；曲目级署名留空
   - 曲目：曲目级署名时选择；专辑级署名留空
   - 制作人：下拉框搜索选择
3. 保存

> 一张专辑通常至少有一条专辑级署名，每首曲目按需添加曲目级署名。

## 5. 修改与删除

- 列表页点击任意记录进入编辑页，修改后保存
- 删除专辑会级联删除其曲目和署名，操作前确认
- 删除仍被署名引用的制作人会失败（数据库外键限制），需要先删除相关署名
- “已发布”取消勾选后，专辑会从前端列表隐藏，但数据保留

## 6. 让前端看到新内容

### 开发模式

开发模式每次请求都实时读取数据库，后台新增内容后刷新浏览器即可看到（包括新增的专辑 slug），无需重启 `npm run dev`。

### 生产模式

静态导出需要重新构建：

```bash
npm run build
```

构建时后端必须在运行（构建过程会从 API 拉取数据），然后把 `out/` 部署到服务器。

## 7. 生产环境注意事项

1. 修改管理员账号与密钥：在 `backend/.env` 中设置

```text
APP_ENV=production
ADMIN_USERNAME=你的用户名
ADMIN_PASSWORD=强密码
SECRET_KEY=随机长字符串
```

`APP_ENV=production` 下若仍使用默认密钥或默认账号，后端会拒绝启动。

2. 使用 PostgreSQL：把 `DATABASE_URL` 改成 PostgreSQL 连接串，并先执行建表。
   连接串格式为 `postgresql+psycopg://用户名:密码@主机:端口/数据库名`，
   例如 `postgresql+psycopg://username:password@localhost:5432/database`，
   其中的用户名、密码、数据库名都需要按你的实际配置修改。

3. 配置 HTTPS：上传接口和管理后台使用密码认证，公网必须走 HTTPS

4. 备份 `backend/media` 目录与数据库，音频和封面属于不可再生资产

5. 访问方式：部署后在本机浏览器打开 `https://你的域名/admin` 即可管理，无需在服务器上安装图形界面。Nginx 需代理 `/admin` 路径（见 README 部署示例），建议同时开启 IP 白名单，避免后台对公网开放。家宽/运营商 NAT 的出口 IP 会动态变化，若出现 403，先查 Nginx 访问日志中 `/admin` 请求的来源地址并更新白名单；更安全的做法是改用 SSH 隧道（`ssh -L 8000:127.0.0.1:8000 用户名@服务器`，然后访问 `http://localhost:8000/admin`），后台完全不暴露公网。

## 8. 常见问题

| 问题 | 原因与处理 |
| --- | --- |
| 新建曲目没有专辑下拉框 | 旧版本问题，已修复；重启后端即可 |
| 下拉框显示 object at 0x... | 旧版本问题，已修复；重启后端即可 |
| 上传返回 401 | 账号或密码错误，检查 `-u` 参数与 `ADMIN_*` 配置 |
| 后台保存后前端不显示 | 开发模式刷新即可看到；生产环境需重新构建并部署，见第 6 节 |
| slug 重复保存失败 | slug 唯一，改为其他标识 |
| 点击播放没声音 | 检查音频路径是否填对、文件是否在 `backend/media` 下、路径是否为相对路径 |
| 管理后台页面 500 | 查看后端终端日志中的 Traceback，通常是字段或配置问题 |
